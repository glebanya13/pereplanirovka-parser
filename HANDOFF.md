# Handoff: парсер решений по делам о перепланировке (Нижний Новгород)

Этот файл — для продолжения работы в Cursor (или любым другим агентом) на
машине с обычным российским интернетом. Здесь весь контекст, чтобы не нужно
было ничего заново объяснять.

## Задача (кратко)

Клиентский заказ (фриланс, не мой проект): собрать сквозные решения по делам
об узаконивании перепланировки/переустройства/переоборудования помещений —
Нижний Новгород, период 2024–2026, по всем 4 инстанциям (районный суд →
областной суд → кассация → Верховный Суд РФ), с 5–7 источников. Результат —
xlsx-опись (несколько листов) на каждый район + общий файл, и архив текстов
решений в docx, разложенный по папкам.

Полный текст исходного ТЗ: `~/Downloads/ТЗ на прасинг по конкретному типу дел перепланировка июль 2026.docx`
Эталонный xlsx-шаблон (структура листов/колонок): скачан и разобран, см.
`src/report/xlsx_builder.py` — там это уже воспроизведено 1:1, повторно
скачивать не нужно.

## ВАЖНО: договорённость про персональные данные — не потерять при продолжении

ТЗ требует для папок «Выигранные»/«Проигранные» брать **полные, не обезличенные
ФИО** истца и представителя, специально выбирая источник, где суд не смог
скрыть эти данные при публикации (обычно это агрегатор судебныерешения.рф,
а не официальный sudrf.ru/bsr.sudrf.ru, которые обязаны обезличивать по
262-ФЗ). Заказчик подтвердил, что делает по ТЗ как есть, но сам не знает
конечную цель использования этих данных.

Договорённость с заказчиком (человеком, который ведёт этот проект, не с
конечным клиентом): реализовать это как отдельный явный шаг, а не скрытую
логику внутри общего пайплайна — см. `src/linking.py::pick_best_source_for_names`.
Если будешь дорабатывать эту функцию — не встраивай её вызов неявно в
скрапинг, оставляй явным отдельным шагом, который легко отключить одним
флагом при необходимости (`--no-full-names` в CLI).

## Технические находки (обновлено)

### судебныерешения.рф
- Поиск: POST `/extended_filter` с формой `extendedSearch[...]`
- CSRF-токен: `extendedSearch[_token]` со страницы `/extended-search`
- Дерево судов: GET `/loadCourtTree/simple` (JSON, поле `branch`, не `children`)
- Ссылки на дела в выдаче: `/{id}/extended` (не просто `/{id}`)
- Текст решения: `div.decision` или `#decision` на странице `/{id}` или `/{id}/extended`
- ID судов Н.Новгорода: Автозаводский=1631, Канавинский=1654, Ленинский=1661,
  Московский=1664, Нижегородский=1666, Приокский=1672, Советский=1677, Сормовский=1679
- Сайт медленный, возможны read timeout — увеличить timeout в `RateLimitedSession`

### sudact.ru
- Поиск: GET `https://sudact.ru/regular/doc/?regular-txt=...&regular-area=1007`
  (1007 = Нижегородская область)
- Результаты отдаются через JS → нужен Playwright (`src/scrapers/sudact.py`)

### sudrf.ru (CMS «Правосудие»)
- С иностранного IP возвращает «Данный запрос некорректен» — нужен российский IP
- Поиск AJAX-driven → Playwright (`src/scrapers/sudrf_cms.py`)
- Карточка дела: `modules.php?name=sud_delo&srv_num=2&name_op=sf&delo_id=NNNN`

### vsrf.ru
- Поиск: `https://vsrf.ru/search/?keyword=...&date_start=...&date_finish=...`

## Установка и запуск

```bash
cd pereplanirovka-parser
source venv/bin/activate
pip install -r requirements.txt
playwright install chromium

# проверить пайплайн xlsx + docx:
python3 -m src.main --demo

# проверить источники:
python scripts/check_sources.py

# реальный прогон (один район):
python3 -m src.main --scrape --district "Автозаводский район"

# все районы:
python3 -m src.main --scrape
```
